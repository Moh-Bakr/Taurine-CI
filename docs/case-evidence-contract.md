# Case evidence contract (standalone proposal)

Status: **local structural contract only; producer trust and runner completeness are unverified.** This document and validator do not enable test selection, change CI workflows, or qualify a partial run for admission. The existing full validation baseline remains authoritative.

## What the validator checks

`.github/policy/case-evidence-contract.rb` accepts a control-generated expected-identity file plus one discovery envelope and one execution envelope. It checks exact envelope keys and schema version, fixed adapter/command identifiers, producer version and status, locked tool-version equality, 40-hex source/control commit identities, manifest/catalog/selection SHA-256 identities, and the JSON report digest. Both reports must use the same runner, config, tier, platform, and expected identity values. The selected-suite list must match the expected set, and its SHA-256 digest is computed from the sorted JSON list.

For each report, the validator derives private case IDs from the same identity fields used by the private audit: runner, config, tier, platform, project, normalized file path, binary ID, package, and title. Vitest and Playwright do not populate binary/package fields, so those identity slots are empty. IDs are used only inside this process to reject duplicates and compare discovery with execution. The validator then returns aggregate counts and a fixed status or error code. It never emits report paths, titles, raw reports, case IDs, or case-ID hashes.

`collection_complete: true` and `producer_status: complete` are producer claims, not proof. The contract also requires nonempty structured reports, parser-valid entries and statuses, exact reporter counts where available, exact execution/discovery ID agreement, and exact agreement with the execution envelope's discovered-ID set. For Playwright, the test-level aggregate status controls the outcome; retry result statuses are validated but cannot override an aggregate `unexpected`, `flaky`, or `skipped` status. The optional `expectedStatus` may be `passed`, `failed`, `timedOut`, `skipped`, or `interrupted`; when omitted it defaults to `passed`. An aggregate expected outcome is accepted only when every attempt matches that expectation, which supports intentional expected failures without treating a mismatched expectation as passing. If the execution report includes `stats`, all four outcome counters (`expected`, `skipped`, `unexpected`, and `flaky`) must be nonnegative integers and reconcile with the parsed outcomes. Reporter errors or malformed error records block the report. A structurally consistent producer can still lie about having invoked the named command; therefore a clean result is `shadow_valid_unverified_producer`, never an admission pass.

Both structural errors and valid-but-nonpassing outcomes return a sanitized `shadow_blocked` JSON object and exit nonzero. Only a structurally reconciled all-passing result exits zero, and it remains unverified shadow evidence.

## Version 1 envelope shape

The envelope retains the private audit's field names: `schema_version`, `phase`, `source_sha`, `control_sha`, `manifest_digest`, `catalog_digest`, `selection_digest`, `collection_complete`, `collection_digest`, `runner_id`, `config_id`, `tier`, `platform`, and `report`. Version 1 adds `producer_version`, `command_id`, `tool_version`, and `producer_status` so a future trusted caller can bind the exact adapter and executable version. An execution envelope also carries `selected_suite_ids` and `discovered_case_ids`, matching the existing private audit contract. The `collection_digest` is SHA-256 over the structured report's JSON serialization, as in the existing private normalizer.

The expected-identity file is generated by trusted control-plane code before project tests run. Its exact fields are `schema_version`, `source_sha`, `control_sha`, `manifest_digest`, `catalog_digest`, `selection_digest`, `selection_mode`, `selected_suite_ids`, `runner_id`, `config_id`, `tier`, `platform`, `project`, `tool_version`, and `repo_root`. It is never read from the source repository. The standalone validator checks that the selection digest matches the sorted selected-suite IDs; a future workflow must independently derive the expected IDs and digests from its protected catalog and source checkout.

## Fixed adapter registry for a future producer

Command identifiers map to fixed arguments in trusted control code. No executable, argument, environment override, test title, or filter expression is accepted from an evidence envelope or source manifest. Resolve runner binaries only inside the checked-out package named by the adapter, validate the resolved path remains inside that package, and pass an argv array with `shell: false`.

| Adapter | Discovery invocation proposal | Execution invocation proposal |
| --- | --- | --- |
| `vitest-desktop` / `desktop-vitest-default` | From `taurine-desktop`: resolved Vitest binary, `list --config vitest.config.ts --json` | Same binary, `run --config vitest.config.ts --reporter=json --outputFile=$RUNNER_TEMP/case-evidence/vitest-desktop.json --includeTaskLocation` |
| `vitest-mobile` / `mobile-vitest-default` | From `taurine-mobile`: resolved Vitest binary, `list --config vitest.config.ts --json` | Same binary, `run --config vitest.config.ts --reporter=json --outputFile=$RUNNER_TEMP/case-evidence/vitest-mobile.json --includeTaskLocation` |
| `vitest-shared` / `shared-vitest-default` | From repository root: resolved Vitest binary, `list --config vitest.packages.config.ts --json` | Same binary, `run --config vitest.packages.config.ts --reporter=json --outputFile=$RUNNER_TEMP/case-evidence/vitest-shared.json --includeTaskLocation` |
| `playwright-desktop` / `desktop-playwright-projects` | From `taurine-desktop`: resolved Playwright binary, `test --config playwright.config.ts --list --project=<one allowlisted project> --reporter=<control-owned case-list reporter>` | Same binary, `test --config playwright.config.ts --project=<one allowlisted project> --reporter=json`; fixed `PLAYWRIGHT_JSON_OUTPUT_NAME` points into `RUNNER_TEMP` |
| `playwright-mobile` / `mobile-playwright-projects` | From `taurine-mobile`: resolved Playwright binary, `test --config playwright.config.ts --list --project=<one allowlisted project> --reporter=<control-owned case-list reporter>` | Same binary and fixed JSON output contract as desktop |

Vitest's three config files are the private manifest's existing desktop, mobile, and shared configurations. The private audit already parses a Vitest list array (`file`, `name`, optional `projectName`) and JSON execution assertions. Before using those IDs for any selector, a pinned Vitest fixture must prove that list names normalize exactly to execution `ancestorTitles + title` across parameterized tests, duplicate names, and projects. The current private runner explicitly avoids per-case filtering until this equivalence is proven.

Playwright uses one fixed invocation per project. Desktop project allowlists are: feedback (`smoke`, `critical`, `shell-browser`), regression (`regression`), benchmark (`bench`), accessibility (`a11y`), and visual (`visual`). Mobile allowlists are `smoke`, `critical`, and `regression`. The public collector currently supports desktop Playwright only; adding mobile Playwright is a separate coverage change. A control-owned list reporter and its exact machine-readable output are not implemented or verified here. The command form above is a proposal, not evidence that the pinned Playwright version supports it.

For every adapter, the producer must capture the exact locked runner version from the source lockfile, execute only the fixed command ID for that phase, verify successful process exit and complete structured output, and derive IDs/status/counts from the parsed report. For execution, the trusted audit re-parses the report and requires exact equality between discovery IDs, execution IDs, and `discovered_case_ids`; additions, omissions, duplicates, malformed records, empty required reports, or non-passing statuses cannot be converted into a clean result. Raw reports and IDs stay in an ephemeral `RUNNER_TEMP` directory with restrictive permissions and are not uploaded as artifacts.

## Gaps and admission boundary

The current public collector keeps file/status/project counts and discards per-case titles; its public manifest contains file globs rather than expected case IDs. The private exact-case parser and audit exist in the ADE source snapshot but are not invoked by the current public workflows. The private publisher that writes case titles to Markdown is not a completeness source and is not used here.

This stage implements only a structural contract and synthetic fixtures. Nextest, doctest, normalized, and native-platform evidence are not supported by this validator. The report itself cannot prove that its producer invoked the registered binary or enumerated every case. A future protected producer must bind the command to trusted control code and the exact source/control/manifest/catalog/selection identities, and must establish runner-specific list/run parity with pinned fixtures and hosted evidence. Until those gates exist, case evidence remains shadow-only and the full concern matrix stays mandatory.
